# @daniilak/chuvash-ornaments

Чувашские геометрические орнаменты как самостоятельные SVG. Все 16 крупных
фигур исходного редактора, 64 композиций, включая 40 авторских, пять фоновых
рисунков, независимое
TypeScript-ядро и необязательные React-компоненты.

Исходные мотивы сохраняют координаты, названия, прямые линии и заливки.
Генератор только размещает, равномерно масштабирует, отражает и поворачивает
их. Созданные композиции — новые сочетания фигур, а не исторические образцы.

Код — **MIT**. Координаты — **CC0-1.0**. См. [NOTICE.md](NOTICE.md).

## Быстрый старт без React

```ts
import {
  generateMotif, generateOrnament, fitFrame,
} from '@daniilak/chuvash-ornaments';

const heart = generateMotif({ motif: 'serdtse', strokeWidth: 0.2 });

const divider = generateOrnament({
  preset: 'divider', motif: 'serdtse', seed: 42,
  width: 640, height: 100, size: 64, gap: 12,
});

// Только код приложения обращается к DOM; ядро работает и на сервере.
container.innerHTML = divider.svg;
container.style.color = '#8b1a1a';

const frame = fitFrame(
  { preset: 'border', motif: 'snezhinka1', seed: 7, size: 32 },
  600, 400,
);
// frame.inset: { top, right, bottom, left } — безопасные отступы в единицах контейнера.
```

Все генераторы возвращают `{ svg, width, height, params, placements }`.
`fitFrame` дополнительно возвращает `inset`.
`placements` — консервативные прямоугольники рисунка с запасом под штрихи,
полезные для проверки размещения. Это не точные контуры отдельных линий.

SVG содержит `xmlns`, `viewBox`, `width`, `height` и
`preserveAspectRatio="xMidYMid meet"`. Фон прозрачный. Нет внешних ресурсов,
DOM, Canvas, сетевых запросов, исполняемого содержимого и глобальных ID.
Несколько одинаковых SVG можно безопасно вставлять на одну страницу.

с синтаксисом импорта JSON, подходящим вашей среде. Главный API и галерея
работают с 16 крупными фигурами.

## Все режимы

```ts
import {
  generateMotif, generateOrnament, generateTile, fitFrame,
} from '@daniilak/chuvash-ornaments';

// Отдельный мотив: поворот по часовой стрелке, отражение координаты X.
const bird = generateMotif({
  motif: 'kuritsa_fill', width: 180, height: 140,
  rotation: 90, reflect: 'x', fillOpacity: 0.82,
});

// Главный мотив в центре, попарно отражённые боковые элементы.
const divider = generateOrnament({
  preset: 'divider', motif: 'kuritsa_fill', motifs: ['kuritsa'],
  seed: 7, width: 640, height: 120, size: 80, count: 3,
});

// Чередование выбранных совместимых мотивов.
const band = generateOrnament({
  preset: 'band', motif: 'serdtse',
  motifs: ['serdtse', 'bolshoe_serdtse'], sequence: 'alternate',
  width: 640, height: 100, size: 48, gap: 12, count: 9,
});

// sequence: repeat — один мотив; mirror — зеркальные пары;
// seeded — воспроизводимый выбор из motifs с отражениями по X.
const seeded = generateOrnament({
  preset: 'band', motif: 'snezhinka1', sequence: 'seeded', seed: 42,
});

// Шахматная плитка — полный повторяемый блок 2×2, обычная — 1×1.
const tile = generateTile({
  motif: 'snezhinka1', layout: 'checkerboard',
  width: 160, height: 160, size: 56, gap: 16, seed: 7,
  color: '#8b1a1a',
});
const backgroundImage = `url("data:image/svg+xml,${encodeURIComponent(tile.svg)}")`;
// element.style.backgroundImage = backgroundImage;
// element.style.backgroundSize = `${tile.width}px ${tile.height}px`;

const border = fitFrame({
  preset: 'border', motif: 'zvezda', sequence: 'mirror', size: 32,
}, 600, 400);
const corners = fitFrame({
  preset: 'corners', motif: 'tree', size: 56, seed: 3,
}, 600, 400);
```

`generateOrnament` также умеет делегировать `motif`, `tile`, `border` и
`corners`; можно восстановить любой результат одним вызовом
`generateOrnament(saved.params)`.

### Как устроена композиция

Полоса использует равные квадратные ячейки. Реальный габарит фигуры вместе
с запасом под штрихи вписывается в каждую ячейку без растяжения. `gap` —
минимум между ячейками; у узких фигур свободное пространство больше.
`count` — верхняя граница количества: если места мало, фигур будет меньше.
В разделителе число фигур нечётное; главный мотив всегда в центре.
Боковые фигуры симметричны относительно центра. Сам главный мотив остаётся
исходным и может быть асимметричным, например птица.

Без явного `motifs` используются небольшие авторские семейства: сердца,
птицы, Кӗскӗ, солнце с Кӗскӗ 3, дерево с цветком, человеческие фигуры.
Для остальных используется сам мотив. Это композиционный выбор библиотеки,
не утверждение о традиционной сочетаемости символов.
`motifs` позволяет явно задать свою последовательность или пул.
`repeat` и `mirror` используют только `motif`; `alternate` перебирает пул,
`seeded` выбирает из него. Seed влияет только на `seeded`, не искажает фигуры
и не меняет толщину линий. Два seed могут дать одну композицию, особенно
при короткой последовательности или одном мотиве.

Плитки содержат целые фигуры с полями по краям. `width` и `height` — размеры
**всего повторяемого блока**, в том числе 2×2 при `checkerboard`.
Границы блока проходят по пустому месту. Пары в шахматном блоке отражены
по X. Чётность и интервалы сохраняются при повторении по двум осям.
Если после `gap` места нет, результат пустой.

Рамка резервирует четыре квадратные угловые области. У border это отражённые
копии главного мотива; у corners одна диагональная пара сохраняет главный
мотив, другая выбирает согласованный акцент согласно sequence и seed. Прямые стороны заполняются целыми фигурами, повёрнутыми
по направлению стороны. Количество и свободные интервалы пересчитываются
по длине стороны. До 124 фигур на сторону, всего до 500. Углы и стороны
не заходят друг в друга. Никакие линии не обрезаются для подгонки.

Глубина рамки ограничена 24% короткой стороны. При глубине меньше 2 единиц
рамка возвращает пустой SVG с нулевым `inset`. Иначе безопасные отступы
включают глубину и небольшой зазор; они не превышают 30% короткой стороны.
У маленьких рамок число фигур уменьшается и масштаб сокращается.
Код приложения обязан разместить контент внутри возвращённого `inset`.

## Параметры и единицы

Все размеры результата — в единицах SVG. Для веб-интерфейса обычно принимают
одну такую единицу за CSS px. Печать может применять другую физическую шкалу.
`strokeWidth` задан **в исходных координатах мотива**, а не в пикселях.
При равномерном масштабировании мотива толщина масштабируется с ним.

| Параметр | Значение по умолчанию | Ограничения / смысл |
| --- | --- | --- |
| `schemaVersion` | `1` | Поддерживается только 1; другая явная версия вызывает `RangeError` |
| `preset` | `divider` | `motif`, `divider`, `band`, `tile`, `border`, `corners` |
| `motif` | `serdtse` | ID одной из 16 фигур |
| `motifs` | Семейство `motif` | До 16 ID; неизвестные удаляются; дубликаты удаляются с сохранением порядка |
| `seed` | `1` | Целое 0…4294967295 |
| `width`, `height` | 640, 120 | 0…16384, единицы результата |
| `size` | `48` | 0…1024; максимальная сторона ячейки, в рамке — глубина, в единицах результата |
| `gap` | `8` | 0…1024, минимум пространства между ячейками; в единицах результата |
| `count` | `9` | Целое 1…128; максимум фигур для полосы / разделителя |
| `strokeWidth` | `0.18` | 0…2, в координатах исходного мотива |
| `fill` | `true` | Выводить только явно заданные исходные многоугольники |
| `fillOpacity` | `0.82` | 0…1 |
| `rotation` | `0` | 0, 90, 180, 270 градусов по часовой стрелке |
| `reflect` | `none` | `x` — менять знак X; `y` — знак Y; `both` — оба; до поворота |
| `sequence` | `seeded` | `repeat`, `alternate`, `mirror`, `seeded` |
| `layout` | `grid` | `grid` или `checkerboard`, только для плитки |
| `color` | `currentColor` | `currentColor` или CSS hex: #RGB, #RGBA, #RRGGBB, #RRGGBBAA |
| `title` | Пустая строка | До 200 символов; непустое название делает SVG доступным изображением |

`generateMotif` по умолчанию использует 160×160 и вписывает фигуру во весь
результат; `size`, `gap`, `count`, `sequence` на отдельный мотив не влияют.
`generateTile` по умолчанию использует 96×96.
У `fitFrame(input, width, height)` обязательные размеры аргументов имеют
приоритет над полями input; неизвестный preset превращается в `border`.
Нормализованные параметры отражают фактически использованные размеры.

`normalizeParams(unknown)` принимает JSON-подобный ввод. Неизвестные поля
отбрасываются; неизвестные enum заменяются значениями по умолчанию.
Принимаются только конечные числа типа number (строки не преобразуются).
NaN/Infinity заменяются значениями по умолчанию, отрицательные числа
ограничиваются снизу, слишком большие — сверху. Нулевые размеры дают
валидный пустой SVG. Число элементов всегда ограничено; бесконечных циклов
из-за входных параметров нет.

## Сохранение и восстановление

```ts
import { normalizeParams, generateOrnament } from '@daniilak/chuvash-ornaments';
const art = generateOrnament({ preset: 'band', motif: 'serdtse', seed: 42 });
const saved = JSON.stringify(art.params);

const restored = generateOrnament(normalizeParams(JSON.parse(saved)));
console.assert(restored.svg === art.svg);
```

Храните **весь `result.params`**, включая размеры, мотивы, цвет, толщину,
раскладку, поворот и `schemaVersion`. Только `{seed, motif}` недостаточно.
`GENERATOR_VERSION` равен 1. Существующие рисунки схемы 1 закреплены
регрессионными SHA-256 снимками. Изменения правил существующих композиций
требуют новой схемы; новые возможности могут добавляться без изменения
старых рисунков. Нормализатор явно отклоняет неизвестную версию, чтобы
не подменить сохранённую композицию незаметно.

Одинаковые параметры дают одинаковую SVG-строку в проверенной среде Node.js.
Используются только арифметика, целочисленный mixer, перестановки координат
и знаков; нет Math.random, времени, счётчиков и тригонометрии. Побайтовое
совпадение между всеми браузерами, CPU и версиями движков не заявляется:
полной матрицы этих проверок нет. Пиксельное сглаживание зависит от
SVG-растеризатора и масштаба даже при одинаковой геометрии.

## Цвет, скачивание и доступность

Inline SVG с `currentColor` наследует CSS `color` родителя. Для самостоятельного
скачанного SVG и CSS `background-image` используйте явный hex-цвет: документ
изображения не наследует цвет страницы. Пример скачивания:

```ts
const art = generateMotif({ motif: 'serdtse', color: '#8b1a1a' });
const url = URL.createObjectURL(new Blob([art.svg], { type: 'image/svg+xml' }));
const link = document.createElement('a');
link.href = url; link.download = 'serdtse.svg'; link.click();
setTimeout(() => URL.revokeObjectURL(url), 1000);
```

Декоративные SVG имеют `aria-hidden="true"`. Для смыслового отдельного
мотива передайте `title`: SVG получает `<title>`, `role="img"` и `aria-label`.
Текст экранируется. HTML/URL/CSS-выражения вместо цвета не принимаются.

## React

```tsx
import {
  Motif, Ornament, PatternBackground, Framed,
} from '@daniilak/chuvash-ornaments/react';

<Motif motif="serdtse" title="Сердце" style={{ width: 120 }} />
<Ornament preset="divider" motif="serdtse" seed={42} className="divider" />
<PatternBackground motif="snezhinka1" seed={7} color="#8b1a1a">
  <section style={{ padding: 40 }}>Контент на фоне</section>
</PatternBackground>
<Framed preset="border" motif="snezhinka1" seed={7} size={32}>
  <article>
    <h2>История</h2>
    <p>Содержимое карточки с безопасным отступом от орнамента.</p>
  </article>
</Framed>
```

Все компоненты поддерживают `className`, `style`, `color`. `Motif`, `Ornament`
и `PatternBackground` принимают параметры ядра. `Framed` принимает параметры
оформления и последовательности, `preset: border | corners`, обычные div props
и children; размеры он измеряет самостоятельно.

`Framed` наблюдает `clientWidth/clientHeight` через ResizeObserver и
пересобирает SVG, меняя количество элементов. SVG находится в абсолютном
декоративном слое. Отступ резервируется с первого рендера независимо от
измерений: `size + min(gap, size × 0.2)` px. Он всегда не меньше фактического
`inset`. Измерение не меняет padding и не создаёт resize/padding-цикла.
Задавайте собственные внутренние отступы на children; padding самого Framed
принадлежит рамке. При явно очень маленьком CSS-контейнере отступ остаётся
стабильным: контент может потребовать прокрутку или разумный min-height.
Сам рисунок уменьшается согласно правилам fitFrame.

Если ResizeObserver отсутствует, рамка измеряется один раз при монтировании.
Для дальнейших изменений размеров в старой среде подключите полифилл.
`PatternBackground` — CSS-фон; если цвет не указан или равен currentColor,
используется `#8b1a1a`. Сам фон декоративный, текст children остаётся доступным.

### SSR

Ядро импортируется и работает без React и без глобальных browser API.
React entry point помечен `use client` для окружений с server components.
Обычный React SSR также поддерживается: `Motif` и `Ornament` рисуются сразу,
`Framed` сначала выводит контент и зарезервированный padding; рамка появляется
после эффекта на клиенте. Начальная серверная и клиентская разметка совпадают.
ResizeObserver создаётся только в effect. Предупреждения гидратации не подавляются.

## Playground и разработка

```sh
npm ci
npm run build
npm run demo
# http://127.0.0.1:5173
```

Playground использует публичные exports собранного пакета. После изменения
ядра выполните `npm run build`; Vite подхватит обновлённый dist.
На странице — 64 композиций, пять готовых фоновых рисунков, отдельная фигура,
разделитель, повторяющийся ряд, фон и два типа рамки. Селект выбора узора
удалён: все 75 вариантов доступны через кнопки категорий «Рамки», «Полосы»,
«Заставки», «Концовки», «Разделители» и «Фоны».

Слева находятся настройки, справа — пример на странице с лёгкой фактурой бумаги. По умолчанию
включён режим «Образец» с чистым узором. В режиме «В тексте» полоса разделяет абзацы, заставка открывает главу,
одиночная фигура завершает рассказ, рамка окружает стихотворение, а фон
оформляет обложку записной книжки. Текст и книжная типографика переведены
на русский, английский и чувашский. Кнопка «Образец» показывает только SVG.
Под кнопками категорий видна компактная сетка соответствующих миниатюр
без подписей; выбранная отмечается рамкой. Доступные имена кнопок сохранены
для скринридеров. Категория сразу показывает первый подходящий вариант. Код под образцом всегда открыт. Меню «Конструктор /
Мотивы» удалено. Фоны представлены повторяемой поверхностью: масштаб
работает и в образце, и на обложке. Панель «Размер плитки» задаёт SVG-единицу
повтора; «Масштаб фона» меняет CSS-размер, сохраняя пропорции фигур.
В режиме «В тексте» рамка обрамляет настоящий выделяемый текст; скачивание
и код в обоих режимах содержат один и тот же чистый SVG узора. Отдельная React-карточка меняет размер через нативную ручку браузера.

Интерфейс полностью переведён на русский, английский и чувашский. По умолчанию выбирается
первый поддерживаемый язык из navigator.languages; если ни один не подходит,
используется английский. Переключатель «Авто / Русский / English / Чӑвашла»
сохраняет ручной выбор в localStorage. При недоступном хранилище переключение
продолжает работать в текущем окне. Локали cv и cv-RU автоматически включают чувашский язык;
доступные имена миниатюр, подписи исходных фигур и все шесть текстовых примеров
также локализованы. Исходные ID, названия и геометрия в библиотеке сохранены.
Отдельная галерея «Исходные фигуры» со страницы удалена.

Подключён локальный CSS Hemingway 1 (Anders Norén, 2014), адаптированный
отдельным слоем для компактной раскладки по референсу Alembic. Внешних
шрифтов и изображений при работе нет. Стили темы — GPL-2.0, собственный код
остаётся MIT; тематическое демо распространяется совместно под GPL-2.0 с
сохранением MIT-уведомлений. Тема и приложение не входят в npm-пакет.

В интерфейсе используются короткие подписи: «Крючки», «Штриховка», «Гребни»,
«Ветви». Канонические имена рецептов и исходные данные библиотеки не изменены.
Вместо Seed показан «Вариант»; для одиночных фигур этот элемент скрыт.
Размер файла вводится числами, а доступный диапазон размера рисунка учитывает
реальные ограничения генератора. Число повторов подбирается автоматически.
Для линейных рисунков не показываются неработающие настройки заливки,
плотность отображается как 0…100%. В демонстрации по умолчанию используется
100% плотности; значение по умолчанию в API остаётся 0.82.

## Фоновые рисунки

`BACKGROUNDS` содержит пять готовых повторяемых поверхностей:

| ID | Рисунок |
| --- | --- |
| `lozenge-net` | Ромбовая сетка с солнцами и сердцами |
| `keske-field` | Смещённые ряды Кӗскӗ с маленькими связками |
| `stepped-carpet` | Плотное поле зубчатых ромбов |
| `woven-lattice` | Плетёная сетка: двойные диагональные нити, просветы в узлах, исходные Кӗскӗ и солнца |
| `cross-stitch` | Штрихованные ромбы и кресты |

```ts
import { generateBackground } from '@daniilak/chuvash-ornaments';
const tile = generateBackground({
  background: 'lozenge-net', backgroundVersion: 1,
  width: 160, height: 160, size: 64, seed: 42, color: '#8b1a1a',
});
container.style.backgroundImage = `url("data:image/svg+xml,${encodeURIComponent(tile.svg)}")`;
container.style.backgroundRepeat = 'repeat';
container.style.backgroundSize = '120px 120px'; // 75% of the exported SVG unit
const restored = generateBackground(JSON.parse(JSON.stringify(tile.params)));
console.assert(restored.svg === tile.svg);
```

```tsx
<PatternBackground background="keske-field" color="#8b1a1a">
  <article>Содержимое страницы</article>
</PatternBackground>
```

`generateBackground` возвращает прозрачную SVG-плитку и полные params.
`backgroundVersion: 1` фиксирует геометрию; другая версия вызывает RangeError.
Ширина и высота — размеры одной повторяемой SVG-единицы, по умолчанию 160×160.
`size` — максимальный размер главной фигуры. Предел равен короткой стороне
плитки, умноженной на `BACKGROUNDS.sizeRatio`; значения по умолчанию
64 / 60 / 136 / 60 соответственно. Пропорции исходных фигур сохраняются.
`strokeWidth`, `fill` и `fillOpacity` имеют тот же смысл, что у остальных
генераторов. В `cross-stitch` fill включает штриховку. Seed выбирает одну
согласованную геометрическую вариацию целого поля; уникальность каждого
числового seed не обещается.

Контуры и фигуры, переходящие границу, намеренно дублируются в соседней
ячейке с точным смещением. Фигуры на краю завершаются при CSS repeat.
Никаких внешних ресурсов, общих ID, масок или clipPath нет. Для фона в CSS
задавайте явный color: currentColor не наследуется отдельным SVG-изображением.
React-компонент, как и раньше, подставляет #8b1a1a вместо currentColor.

Фоновые рецепты имеют фиксированный состав: motif/motifs/sequence/layout,
rotation/reflect, gap/count не меняют их геометрию. Для своей фигуры и
произвольной сетки остаётся прежний `generateTile` и шестая кнопка в «Фонах».
В демо эта базовая плитка по умолчанию использует полный шахматный блок 2×2.

Плитки и параметры: `examples/backgrounds/`. Обзор повторов 4×3:
`docs/backgrounds.png`. Генерация включена в `npm run examples:render`.

Плетёная сетка адаптирует конструкцию [PatternFills crosshatch](https://github.com/iros/patternfills/blob/master/src/patterns/6-other/crosshatch.svg)
(MIT, Irene Ros, 2014). Простой крест заменён двойными нитями с явным
чередованием сверху/снизу, добавлены исходные фигуры и прямоугольное
вписывание. Фон прозрачный, белых заплаток и общих SVG ID нет.
Лицензия включена в `data/LICENSE-PatternFills`, изменения описаны в NOTICE.

не generateOrnament.

декораций; `placements` по-прежнему описывает нетронутые исходные мотивы.

отдельным узором. Исходные 16 фигур и прежние 18 композиций сохранены.

```ts
const border = generateComposition({

  width: 960, height: 180, size: 96, seed: 42,

```

`BOOK_STUDIES` содержит ID, тип, локализованные названия, признак `twoTone`
и размер по умолчанию. Пять двухцветных рецептов принимают `accentColor`:
по умолчанию кирпичный #a64c38, у шевронов охристый #c4a56d;
основной цвет #292824. Стежковая кайма использует одну краску #a64c38.
Оба цвета входят в сохраняемые params и SVG; React `Composition` принимает
те же параметры. `fill:false` оставляет контуры. Полосы имеют не более 64
целых ячеек, gap задаёт расстояние между ними (множитель 0.12).
Заставка из трёх панелей — единичная композиция, gap/count её не меняют.
Крупный обзор: [шесть новых узоров](docs/reference-studies.png).
SVG и полные параметры: `examples/book-studies/`.

Метаданные `COMPOSITIONS.kind` различают band, divider, separator, rosette и frame.
Для розеток используются квадратные размеры по умолчанию 400×400 и size=320;
size — максимальный диаметр композиции, при вписывании пропорции сохраняются.
`book-frame` по умолчанию имеет 720×400, size=72 и возвращает `inset` —
безопасные отступы для настоящего текста. Глубина ограничена 22% короткой
стороны; зубчатые узлы соединены ромбовидными перемычками, сохраняя отступы.
При глубине меньше 2 единиц рамка пуста с нулевым inset. Стороны пересчитываются
при изменении размеров, каждая имеет не более 64 внутренних узлов.

Штрихованные ромбы состоят из реальных SVG-отрезков. Их концы вычисляются
пересечением горизонтальных сканирующих линий с внешним и внутренним
контурами; clipPath, mask и разделяемые ID не используются. Розетки собираются
точными поворотами на 90° новых фиксированных элементов — без тригонометрии
и случайного смещения точек. Это новые геометрические композиции по
предоставленным примерам, а не заверенные обводки исторических иллюстраций.

Композиции используют seed, width, height, size, gap, count, strokeWidth, color,
fill, fillOpacity и title. Повороты/отражения заданы самим рецептом; поля
базовых раскладок motif/motifs/sequence/layout не меняют авторский состав.
Размеры — единицы результата, как у остальных генераторов. count — максимум
целых ячеек (не более 64). Исходные фигуры сохраняют strokeWidth в своих
координатах; декоративные линии первых шести рецептов используют номинальную высоту
10 единиц и ограничены 3.5% высоты ячейки (в версии 1 — 12 и 2.5%). У остальных книжных рецептов
линейные детали построены на собственной фиксированной координатной сетке:
эталон strokeWidth=0.26 соответствует исходному весу детали; множитель
толщины равен min(2, strokeWidth/0.26), а strokeWidth=0 отключает штрихи.
Для контуров незалитых многоугольников ширина в сетке равна
min(0.6, 1.2×strokeWidth), затем масштабируется с композицией. Силуэты заливок
остаются неизменными. fillOpacity действует только на заливки. Начиная с версии 2 fillOpacity по умолчанию равна 1, strokeWidth — 0.36;
исходные мотивы и базовые генераторы сохраняют прежние значения по умолчанию.

Это не точные обводки книжных иллюстраций и не заявленные исторические
образцы. Новые ступенчатые силуэты и кольца нарисованы как геометрические
этюды; полилинии и заливки исходных 16 фигур не изменены. Внутреннее
перекрытие контуров орнаментальной каймы задумано как часть композиции.


`branch-medallion` использует зеркальную симметрию по двум осям; гребни,
ветви и белые окна заданы явно. `lozenge-ligature` соединяет соседние ячейки
едиными полилиниями, чтобы на стыках не появлялись тёмные засечки.
`horn-band` чередует зеркальные рогатые пары с тонким центральным деревцем.
`comb-band` использует настоящую штриховку и общие поперечные гребни.
`toothed-diamonds` строит кольца с открытым ромбовидным центром и зубцами.
`lozenge-frame` возвращает inset = 1.15 глубины и обрамляет вложенные ромбы
двойной тонкой линией. Все формы сохраняют пропорции при вписывании.
У четырёх новых полос size ограничивается min(0.8×height, 0.7×width) / 1.3;
gap задаёт промежуток в масштабе 0.2, count ограничивает число целых ячеек.
Seed выбирает согласованный вариант всей полосы; у одиночного медальона
seed/gap/count не меняют фиксированную фигуру.

Готовые SVG с параметрами: `examples/ornaments/`. Обзор на белом фоне:
`docs/new-compositions.png`; шесть предыдущих книжных этюдов — `docs/book-additions.png`,
шесть новых — `docs/more-ornaments-large.png`. Пересоздать: `npm run examples:render`.

```sh
npm run typecheck       # ядро, React и код playground
npm test                # геометрия, воспроизводимость, SVG raster, SSR/гидратация/resize
npm run demo:build      # статическая сборка в demo-dist/
npm run check:demo      # функции собранной страницы: язык, все варианты, код
npm run check:package   # dry-run, tarball, offline-установка, Node и типы потребителя
npm run check           # весь цикл; архив .tgz остаётся в корне
npm pack --dry-run
```

`dist/` — ESM и декларации. Пакет содержит только dist, исходные JSON-данные,
лицензии, README, NOTICE и package.json. Playground, тесты, исходные снимки
редактора и Alembic, dev-зависимости в tarball не входят.
Архив создаётся локально; команды `check` не публикуют его.

Подробности реализации и QA — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
и [docs/VALIDATION.md](docs/VALIDATION.md) в исходном проекте.

## Происхождение и точность

Источник: [daniilak/chuvash-patterns](https://github.com/daniilak/chuvash-patterns)
и [редактор](https://daniilak.ru/pattern_editor).
Снимок данных и исходников получен 31 октября 2026; revision и SHA-256
записаны в `sources/manifest.json`. В установленном пакете всё работает офлайн.

Координаты могут быть отрицательными и смещёнными, как у «Цветка».
Bounding box учитывает сегменты и fills. Y направлена вверх в данных;
производная геометрия инвертирует Y для SVG. Прямоугольные повороты точные.
Сегменты соединяются в полилинии по однозначным продолжениям. Линии имеют
`butt` linecap, `miter` linejoin, miterLimit 8. Запас равен четырём толщинам
штриха с каждой стороны плюс 0.001 исходной единицы. Это консервативный
запас для острых соединений; ячейки могут содержать заметное свободное место.
Замкнутые контуры автоматически не заливаются. Птица с заливкой сохраняет
единственный исходный многоугольник.

[Alembic Ornaments](https://github.com/lauriparonen/alembic-ornaments) послужил
референсом для компактного API, seed, SVG и измеряемой React-рамки.
Растительные мотивы, алгоритмы роста и код реализации не заимствованы.

## Ограничения первой версии

- Только прямоугольные повороты и равномерное масштабирование; исходные
  пересечения внутри фигур сохраняются.
- Полосы конечные и центрированные, плитки повторяются через CSS. Рамки
  состоят из отдельных целых мотивов, без соединительных линий.
- `color` принимает hex и currentColor; произвольные CSS-функции не поддерживаются.
- Seed управляет выбором и отражением в режиме seeded. Он не гарантирует
  уникальную композицию для каждого числа.
- Проверены Node.js, браузерный playground и jsdom React hydration; отдельная
  матрица Safari/Firefox/React 18 не выполнялась.
- Перед публикацией необходимо повторно проверить имя, права npm scope и
  учётную запись. Сам npm publish и hosting входят в отдельную задачу.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает и проверяет playground при push
в main, затем размещает только demo-dist в GitHub Pages. В настройках Pages
используется источник GitHub Actions. Относительный Vite base позволяет открывать

Автоматическая публикация npm не настроена.

### Композиции по мотивам чувашского текстиля

Три новые авторские адаптации построения старинных вышитых изделий,
без заявления о точном воспроизведении музейных предметов:

| ID | Категория | Построение |
|---|---|---|
| `wedding-cloth-frame` | Рамка | Многослойная кайма, угловые розетки и побеги, свободное центральное поле |
| `masmak-tiered-band` | Полоса | Чередование угловатых цветов и ступенчатых крючков между мелкими рядами |
| `sara-paired-tailpiece` | Концовка | Две узорные подвески с ярусами и геометрической бахромой |

Метаданные доступны как `TEXTILE_STUDIES`. Все три рецепта поддерживают
основной и второй цвет, размер, толщину линий, контур и плотность заливки.
У рамки и полосы интервал меняет частоту крупных фигур. Рамка возвращает
проверенный по растровому изображению `inset` для размещения содержимого.

SVG/PNG и параметры: `examples/textile/`. Листы визуальной проверки:
`docs/textile-review/final-*.png`, общий лист — `docs/textile-review/collection.png`.
Воспроизведение: `npm run build && node scripts/render-textile-studies.mjs`.

Источники построения: [свадебные платки в собрании РЭМ](https://www.ethnomuseum.ru/files/PDF/Library/Ornamentika/kashpar.pdf),
[головные повязки и украшения «Паха тĕрĕ»](https://www.paha-tere.ru/blogs/istoriya-paha-tere/ukrasheniya-chuvashey),
[сарӑ из Туймазинского историко-краеведческого музея](https://ar.culture.ru/ru/subject/sara-sary).

### Угловые наборы и сложные разделители

`CORNER_DIVIDER_STUDIES` содержит три набора из четырех углов
(`brocade-corners`, `garden-corners`, `lattice-corners`) и три разделителя
(`embroidered-knot-divider`, `paired-bloom-divider`, `stepped-lace-divider`).
Это современные геометрические разработки в продолжение текстильной серии.

Угловые наборы находятся в категории «Рамки», оставляют свободную середину
и возвращают `inset`. Размер углов меняется отдельно; соединительной каймы нет.
Разделители сохраняют размер центрального мотива при изменении ширины файла,
дополняя концы мелкими орнаментами. Поддерживаются оба цвета, контур,
плотность заливки и толщина линий. Все изображения не содержат надписей.

SVG/PNG, отдельные верхние левые углы и параметры: `examples/corners-dividers/`.
Общий лист и проверка цвета, контура, одного цвета и темного фона:
`docs/corner-divider-review/`. Воспроизведение:
`npm run build && node scripts/render-corner-divider-studies.mjs`.
